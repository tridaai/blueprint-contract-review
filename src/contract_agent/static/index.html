How it works

intake + clause segmentation → per-clause extraction → injection screen → per-clause playbook review (rules + LLM cross-check) → computed facts (posture, absence detection) → playbook retrieval → assessment (bounded tool loop) → scored options → draft packet + counterparty response → self-verify → independent review → guardrails → counsel gate. Code computes the verdicts; the model does language work; counsel decides.

3 · Counsel gate

Approval records counsel's decision on the packet. Nothing is emailed, sent, or filed by the agent; with ACTION_WEBHOOK_URL configured, the approved packet is routed to that endpoint instead.

Trida AI blueprint — Apache 2.0. Runs fully offline with the template backend; set MODEL_BACKEND to a provider (or Ollama locally) for the real LLM paths. Production topology: PostgreSQL (records, checkpoints, pgvector) + S3 documents — see docker-compose.yaml.
